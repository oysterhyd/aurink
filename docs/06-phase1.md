# 06 · Phase 1 实施计划

> 状态：**进行中**（用户 2026-11-01 通知开工），进度见 §9。
>
> 本文说明 Phase 1 怎么做：顺序、范围、任务要点、验收。任务卡的交付物和估时见 [05 §6](05-delivery-plan.md)，二者冲突时以本文为准。

## 1. 目标

Phase 1 结束时（M1）要得到一个能日常试用的单文件编辑器：

1. 从菜单、命令行或双击打开 `.md`，看到排版后的文档。
2. 光标到哪，哪里显示 Markdown 标记。输入法、撤销、选区都正常。
3. 保存不改动没碰过的字节。进程被杀后能恢复未保存内容。
4. 能切到源码模式再切回来。
5. 外观按 Ink & Aurora 基线，亮暗主题和低功耗路径都可用。

文件夹工作区、文件树、命令面板、查找替换、表格工具条都在 Phase 2。

## 2. M1 的范围

05 §7 写的是“P0 语法集正确渲染”和“M1 基线全部通过”，但部分 P0 视觉和基线内容排在后面的阶段。M1 按下面的表验收。

### 2.1 语法

| 段落、标题、强调、加粗、删除线、行内代码、链接、自动链接、转义、实体、软硬换行 | 完整实现，内联显隐 | — |
| 列表、任务列表、引用、代码块、分隔线、本地图片 | 完整实现（FE-1.2） | — |

| 脚注 | 引用和定义都显示为淡色源码 | FE-1.4 |

任何一种语法都不能丢字节，也不能让文字进入隐藏区。

标题栏按基线实现，不放测试按钮。基线里有、但功能排在后面的控件这样处理：

| 控件 | M1 |
|---|---|

### 2.4 M1 明确不做

- **大文件：** 超过 5 MB 的文件在 M1 提示后不打开，大文件模式在 BE-1.8。
- **外部修改：** 不监听文件变化。保存时发现磁盘已变，停止写入，胶囊显示“有冲突，未写入”，并保留恢复副本。冲突横幅在 FE-2.5。
- **剪贴板：** M1 只有 Markdown 文本的复制、剪切、粘贴。HTML 和图片在 BE-1.6、FE-1.5。
- **错误提示：** 用通知显示，对话框和横幅在后续任务卡。
- **平台：** 只在 Windows 真机验收。macOS、Linux 只有构建和无窗口测试，IME 仍标为未验证。

## 4. Codex 批次的做法

### 4.1 开始前，负责人要准备

1. **一致性测试：** 把该接口的 `internal/contracttest` 套件写好并提交，内容来自 04 §4 的不变式。这样验收标准不是 Codex 自己定的。
2. **任务说明：** 写到 scratchpad，包括范围、要读的文档、本文对应的要点、完成标准和第 4.2 节的约束。

05 §6 现状里“其余接口的套件随实现一起写”已改为这个做法。

### 4.2 启动

```bash
git worktree add -b codex/<卡ID> D:/mygo/project/Aurink_claude-wt/<卡ID> main
codex exec -m gpt-6.1-sol -c model_reasoning_effort="xhigh" --approve-for-me -C D:/mygo/project/Aurink_claude-wt/<卡ID> -o <scratchpad>/codex-<卡ID>.md < <scratchpad>/brief-<卡ID>.md
```

Codex 作为后台命令启动，进程退出后负责人被唤醒。这组参数在批次 1 实际跑通 [实测]。`--approve-for-me` 没有沙箱，所以每份任务说明都写明：

- 不提交、不推送、不切分支，只改自己 worktree 内的文件。
- 不改 `internal/contract`、`internal/contracttest`、`docs/`。认为契约要改时，停在那一项并在最终报告里说明原因和最小反例。
- 不添加 05 §3.3 白名单之外的依赖，不升级 MyGo。
- 测试断言用字节、节点和计数，不用墙钟等待。

### 4.3 验收

Codex 的报告不算证据。负责人按顺序检查：

1. `git status` 和 `git diff`：改动范围在任务内，受保护的目录没有变化，逐文件读过 diff。
2. `scripts/gate.ps1 -AllTargets` 通过。
3. `go test -count=1 -cover` 达到覆盖率要求（core ≥ 80%；`projection`、`editing`、`document` ≥ 90%），并跑批次要求的属性测试和基准。
4. 抽查测试：故意改坏一处实现，确认测试会失败。
5. 通过后由负责人在分支上提交，合并到 `main` 后再跑一次门禁，然后推送并删除 worktree 和分支；有问题就在同一份说明上追加问题退回，或者负责人直接修。

## 5. 后端任务要点

05 的交付物和验收继续有效，下面只写 Phase 0 之后新增或修正的内容。

### 批次 1：BE-1.1 Text、BE-2.1 FileStore

- 通过现有的 `contracttest.TestText`、`TestFileStore`。
- 原子替换用标准库 `syscall` 调用 `ReplaceFileW`，失败时回退 `MoveFileEx`，不引入 `x/sys`。
- 权限、硬链接、不可创建临时文件的回退路径参照 MyGo `document_file.go`。
- 故障注入：在写临时文件、`fsync`、替换这几步分别失败，原文件都不变。
- 语料“读→写”字节一致 100%，含 BOM、UTF-16、CRLF、混合换行、无尾换行。

### 批次 2：BE-1.2 Markdown

依据 ADR-003 和 `spikes/s3-ast/REPORT.md`，**这批的验收以它们为准**：

| 要求 | 说明 |
|---|---|
| 内容行映射 | `Block.Lines` 逐行映射在语料上 100%（CR-003），不再要求严格前缀 |
| 覆盖规则 | 04 §4.2.8、§4.2.9，语料和 3 个种子各 1 万步随机编辑都无缝无叠 |
| 隐藏文本 | **Lead、Trailer 里只能有容器语法、空白和行终止符。** 引用内只有链接定义时，生成 `BlockLinkDef` 叶子；表格行多余的单元格生成额外的 `BlockTableCell` 叶子。S3 的 2 种情形都要有回归测试 |
| BlockID | CR-004 的存活规则；3 个种子各 1 万步，ID 唯一且不复用 |
| 增量等价 | 每一步与全量解析比较拓扑、种类、范围、内容行和内联，不能只比 HTML |
| parser.Edit 反例 | 相邻缩进代码块、引用与脚注缓存失效两类反例保留为测试，回退触发时明确计数 |
| 不可变快照 | 见下 |
| 击键路径性能 | 不能重建全部块。200 KB 文档上单次增量更新 ≤ 2 ms（基准，p95），且分配量不随全文内联数增长（计数断言） |

**不可变快照是这批最大的设计点。** `parser.Document.Edit` 原地修改解析器 [源码 `ui/markdown/parser/document.go`]，内联又是惰性的，而契约要求旧版本 AST 在任意 goroutine 都可读。实现时：

- AST 快照不能持有会被下一次 `Edit` 修改的解析器状态。块数据由适配层保存，未变化的块在版本之间结构共享。
- 惰性内联只从快照自己的源码字符串解析，不能回到已修改的解析器。如果做不到，就在更新时解析受影响的叶子块，并把分配计入性能断言。
- 测试：保留旧快照，连续编辑后旧快照的块和内联不变；多个 goroutine 同时读旧快照、主线程继续编辑。`-race` 需要 cgo，能跑就跑，跑不了要写明 [待验证]。

Front Matter 只做识别和块生成，YAML 语义留给 BE-1.7。

### 批次 3：BE-1.3 Projection

- 通过 04 §4.3 的全部不变式，黄金测试 ≥ 150 例。
- **`RevealInline` 专项（ADR-001 最大遗留风险）：** 对语料的每个叶子块，模拟光标从块首逐步走到块尾再走回来，每一步都用新的 Reveal 重新投影。断言光标的源码偏移严格前进或后退、不卡住、不跳过可见字素，并且 `ToSource(ToDisplay(s)) == Snap(s)`。
- 缓存复用按 04 §4.3.6，不能以 `Sig` 相同为复用条件。
- 只实现 §2.1 里 M1 要的片段类型和规则；规则表要能在后续添加。

### 批次 4：BE-1.4 Document

- 04 §4.1 全部不变式。3 个种子各 1 万步，每步与字符串模型比较；任意步撤销和重做后文本、选区都回到原状态。
- `DocEvent.Dirty` 要包含“ID 不变但引用定义变化”的块（04 §4.2.6）。
- 历史上限 1000 步或 64 MB，用计数和字节数断言。合并的 1 秒窗口要能注入时钟，不用真实等待。
- 200 KB 文档上 `Apply`（含增量解析和事件）p95 ≤ 4 ms（基准）。这是 8 ms 击键预算里留给核心的部分。

### 批次 5：BE-1.5 Editing

- 04 §4.4；每条规则 ≥ 3 个黄金例，覆盖 CRLF、嵌套列表、CJK。
- 每个例子都断言最小改动：编辑范围之外的字节不变。
- 输入规则和触发它的键入分属两步历史，撤销先撤自动格式化。
- 表格只保证基础意图不破坏文档。单元格导航和增删行列在 BE-1.6。

### 批次 7：BE-2.2 Settings、BE-2.3 Commands

- core 不能导入 mygo，配置目录由构造函数传入，`PathUserData` 由 app 提供。
- 默认键位按 02 §7。零冲突测试和三平台显示串测试都要有。
- BE-2.3 已完成。待真机确认（INT-1.1）：`Alt+数字` 和原生菜单的 Alt 行为是否冲突；`Ctrl+Shift+F` 和微软拼音简繁切换的冲突（来源是厂商文档，未实测）。

### 批次 8：BE-2.4 DocSession v1

- 恢复目录由构造函数传入。时钟和去抖定时器可注入，测试不等真实时间。
- 恢复副本用 `FileStore` 同样的原子写，保存成功或主动关闭后删除。
- “kill 进程→重启恢复”：`tests/e2e` 启动一个辅助进程，编辑后强制结束，再启动并断言内容。
- 不含外部修改监听（BE-2.7）。保存时的冲突要完整：`expect` 不符时不写入，进入 `Conflict` 状态，`KeepMine`、`LoadTheirs` 可用，自动保存暂停。

## 6. 前端任务要点

### FE-1.1 编辑引擎（批次 6）

- 从 `spikes/s1-liveedit` 移植结构（自滚动、双形态缓存、Fenwick、IME），改为面向 `contract.DocumentModel`、`Projector`、`Editing`，所有写入都经过 `Apply`。
- S1 没做的都在这张卡里做：内联显隐、词级移动、双击和三击、拖选自动滚动、复制剪切粘贴（Markdown 文本）。
- **验证 `RevealInline` 的真实手感**：光标穿过隐藏标记时，块高变化不抖动，IME 候选框跟随。
- 每次键入 O(块数) 的路径要改掉（S1 §6.7），排版缓存失效改用 `DocEvent.Dirty`。
- 单独测冷启动，查清 S1 那次 1915 ms 的首帧（ADR-001）。
- `Controller.Focus()` 没有 `*ui.Context`，要记下请求并在下次构建时执行（S1 §5）。

### FE-2.1 Theme + Kit（批次 10）

- 字体从 `spikes/s4-look/fonts` 移到 `resources/fonts`，用 `RegisterFont(data, "Noto Serif SC")` 显式命名（ADR-004）。
- 玻璃、主题溶解、低功耗切换从 `spikes/s4-look` 移植，按 ADR-004 的写法。
- `views/motion` 提供“外框飞行、内容按最终尺寸布局并裁剪、由常驻元素驱动淡入”的公共写法。
- 只实现 M1 用到的组件和令牌；05 卡片里的其余组件在用到它们的任务卡里完成。
- “减少透明度”是应用设置，不是系统偏好。

### FE-1.2 块视觉（批次 11）

- 按 §2.1。表格用普通网格，脚注、HTML、Front Matter 用淡色源码。
- 复选框点击只改 1 字节，用断言验证。
- 块组件走 03 §6.5 的注册表，后续语法不改引擎核心。

### FE-1.3 源码模式（批次 12）

- **风险：** `editor.Buffer` 会归一化混合换行 [实测 01]。求差写回时不能把归一化当成用户修改。
- 验收加两条：语料 `edge` 里的混合换行文档切到源码再切回，不编辑时字节完全一致；编辑时只改动编辑到的字节。如果 Buffer 做不到，就在 M1 前提出方案，不能接受静默改写换行。

### FE-2.2 Shell（批次 13）

- 按 §2.3 实现标题栏。S4 的测试按钮不进入产品。
- 窗口按钮要跟随应用主题（ADR-004 的未验证项），在这张卡里验证。
- 欢迎页 M1 静态。按钮只放已有功能：新建、打开文件。

### INT-1.1 组合根（批次 14）

- 只接真实实现，不做 mock 切换开关。视图测试需要替身时，在测试包里写窄接口的小实现。
- 单实例、命令行参数、文件关联在 Windows 上实际验证。
- 菜单项全部来自命令注册表，只注册 M1 已实现的命令。

### QA-1.1、QA-1.2、QA-1.3（批次 9、15）

- 按 05 的卡片执行，结果写入 `reports/quality.md`。
- QA-1.2 的 ≥ 40 个场景中包含 §7 的每条风险各至少一个回归。

## 7. 主要风险

| 风险 | 影响 | 应对 | 发现时点 |
|---|---|---|---|
| 不可变快照和原地 `parser.Edit` 冲突 | 击键变慢，或旧快照被改 | §5 批次 2 的设计要求；不达标时负责人重做适配层 | 批次 2 |
| `parser.Edit` 还有其他缺陷 | 增量结果错误 | 随机等价测试；保守回退全量解析；最小反例记入报告 | 批次 2 |
| `RevealInline` 光标不顺 | 核心体验差 | 批次 3 属性测试；批次 6 真机。不可接受时由用户决定是否默认改为块级显隐 | 批次 3、6 |
| 串行工期长 | M1 比预期晚 | 批次 2 后重估；前后端都按批次提交，随时可看进度 | 批次 2 |
| Codex 流程没跑过 | 第一批可能受阻 | 批次 1 规模小；不可用时告诉用户，不擅自改由负责人写后端 | 批次 1 |
| 源码模式换行归一化 | 破坏无损承诺 | FE-1.3 的两条验收 | 批次 12 |
| 只有核显的机器帧率、首次切主题 279 ms | 观感卡顿 | M1 真机再测；不达标时走 ADR-004 的后备 | 批次 15 |

## 8. M1 验收

05 §7 的条件按本文 §2 的范围解释。必须有下面的证据：

| 条件 | 证据 | 谁来 |
