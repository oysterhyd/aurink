## 1. 目标

Phase 2 结束时（M2）要得到一个能管理一个文件夹的编辑器：

1. 打开文件夹，在文件树里新建、重命名、移动、删除到回收站。
2. 用快速打开、命令面板、大纲、全文搜索和查找替换找到内容。所有已实现的功能都能从命令面板到达。
3. 文件被其他程序修改或删除时，内容不丢，状态看得见，可以选择怎么处理。
4. 重启后回到上次的文件夹、标签、光标和滚动位置。
5. 能编辑表格，能粘贴或拖入图片，能粘贴网页和 Word 内容，脚注按最终样式显示。
6. 能导出 HTML，能复制为 HTML 或 Markdown。

公式、Mermaid、Front Matter 页眉、阅读和专注模式、斜杠菜单、格式条、设置界面都在 Phase 3。

## 5. 设计决定

负责人在批次 1 落实。这些是任务卡没写清、Codex 不该自己决定的地方。

| # | 问题 | 决定 |
|---|---|---|
| D1 | core 不能导入 mygo，但监听要用 `mygo.WatchFiles` | 在 `contract` 加窄接口 `FileWatcher`，由 `adapters/watch` 实现。Workspace 和 DocSession 共用它，测试用可手动触发事件的替身 |
| D2 | 自己保存也会触发监听事件 | 比较文件戳和 `Session` 记录的 `expect`，相同就忽略。事件和保存同时发生时以戳为准，不靠时间窗口 |
| D3 | 工作区外的文件也要监听 | DocSession 监听每个打开文件的所在目录（不递归），不管是否在根目录下。两边各自监听，互不依赖；同一目录被监听两次的开销可以接受（批次 1 修订：原写“已被根目录覆盖的不重复监听”，会让 DocSession 依赖 Workspace 的降级状态） |
| D4 | 监听可能丢事件（超限、溢出、休眠） | 窗口获焦时对所有打开的文件做 `Stat` 复查（03 已写）。溢出事件也触发一次复查和可见目录刷新 |
| D5 | 文件树里改名或移动已打开的文件 | 由 Workspace 发 `WsRenamed`，DocSession 更新路径，不算外部修改。外部改名只在同目录且能确认时跟随（03 §5），否则按删除处理，内容保留 |
| D6 | 移动父文件夹 | 其下所有打开的文档一起更新路径，有矩阵测试 |
| D7 | 删除到回收站的撤销 | `Shell.TrashItem` 没有还原接口 [源码]。删除前确认，通知里不放撤销。02 §5.6 的撤销只用于拖拽移动，撤销就是反向移动 |
| D8 | 删除已打开且未保存的文件 | 确认框说明有未保存内容。文档进入 `Deleted` 状态并保留恢复副本，不自动关闭标签 |
| D9 | 会话状态存哪 | `PathUserData/session.json`，用 `FileStore` 原子写，损坏时按空会话启动并备份。内容：根目录、标签路径与顺序、活动标签、展开目录、每个文档的光标和滚动。目标文件已不存在时跳过，并发一条通知。`Settings.RestoreSession` 控制是否恢复 |
| D10 | 光标和滚动谁来存 | DocSession 不知道视图。shell 在切换标签、失焦和关闭时把视图状态交给 `Sessions`。滚动存“块序号 + 块内偏移”，不存像素，字号和宽度变了也能回到原处 |
| D11 | HTML 转 Markdown 需要解析器 | 把 `golang.org/x/net/html`（BSD、纯 Go）加入 05 §3.3 白名单。转换结果不能含 `<script>`、事件属性和 `javascript:` 链接 |
| D12 | RTF | 剪贴板同时有 HTML 时用 HTML。只有 RTF 时支持段落、粗体、斜体、换行，其余取纯文本。不追求完整。RTF 的读取方式 [待验证]（`Clipboard.ReadFormat`） |
| D13 | 导出的主题样式 | `core/export` 不能导入 `views/theme`。CSS 内嵌在 `core/export`，`tests/` 里加一个测试，核对它和 `theme.For` 的色值一致 |
| D14 | 面板只列可用命令 | 只注册已实现的命令，`Enabled` 反映当前上下文。不留点了没反应的项（06 §2.3） |
| D15 | 全文搜索和文件树的忽略规则 | 同一份规则，放在 `core/workspace`，`core/search` 通过参数接收，不互相导入 |
| D16 | 源码模式的查找 | `ui/editor` 的高亮能力 [待验证]。FE-2.5 开始时先确认；做不到时只高亮当前项，并记入差异 |
| D17 | 导出的代码高亮 | 词法分析在 `ui/editor`，core 不能导入。`ExportOptions.Highlight` 由 app 注入，`core/export` 只负责输出 `tok-` 类名的 span；为 nil 时输出纯文本 |
| D18 | 回收站 | `Shell.TrashItem` 在 mygo 里，core 不能导入。加窄接口 `contract.Trasher`，由 `adapters/trash` 实现 |
| D19 | 监听超限降级后 | 每个已加载的目录单独监听（不递归）。根目录以外的未加载目录不监听，展开时再加 |

契约改动按 05 §4 在同一次提交里同步实现、`contracttest` 和 04 文档。

## 6. 任务要点

### 批次 2

**BE-2.5 Workspace**
- 目录操作全部异步，事件回主线程（04 §2）。排序：文件夹优先、自然排序。
- 同名、无权限、路径不存在都返回明确错误码，文件树靠它显示提示。
- 集成测试用真实临时目录，外部增删改名都要被报告。超限降级用很小的 `MaxEntries` 测。等事件用通道加超时上限，不用固定睡眠。
- 也实现 `Assets`（文件名冲突时加序号，目录按设置）和 `Recent`（去重、上限、持久化）。

**BE-2.6 Search**
- 05 的预算：1 MB 文档查找 < 5 ms，1 万文件目录搜索可取消。
- 正则用标准库 `regexp`（RE2，没有灾难性回溯）。`Range` 是字节偏移，`Preview` 里的 `Hit` 要能处理多字节字符和超长行截断。
- `Fuzzy` 的 `Positions` 是 rune 下标，FE-2.4 用它高亮，CJK 要有测试。

**BE-2.8 导出 HTML**
- 按 D13。用 `contract.Text` 和 `AST` 导出，不用 `parser.HTML()` 的结果，只拿它做结构对照。
- 文档里的原始 HTML 按 02 同样的安全范围处理。导出的文件可能被别人打开，不能原样放行脚本。
- 取消和 `OnProgress` 都要有测试。

### 批次 3：BE-1.6 Editing v2

- 05 的核心标准：表格操作不改动表格外的字节。源码不自动重排，只有“格式化表格”才重排（02 §5.8）。
- 先查 `core/editing` 已有的表格命令，再定缺口，不重写。
- 样本放 `testdata/paste/`：Word、网页、Google Docs 各至少 5 个，真实来源的 HTML，不用手写的简化版。
- 负责人照 06 §5 的做法，写黑盒表验收，覆盖率不当证据（BE-1.5 曾在 98.3% 覆盖率下破坏表格）。

### 批次 4：BE-2.7 DocSession v2

- 05 要求冲突矩阵 ≥ 12 例。行是磁盘事件（修改、删除、改名、删除后重建），列是文档状态（未编辑、已编辑、保存中、已冲突、只读）。不适用的格子写明原因。
- 自动重载走 `Replace`，能撤销，选区尽量保持。
- 自动保存在冲突和已删除状态下继续暂停，恢复副本继续更新。

### FE-2.4 命令面板（批次 7）

- 面板是模态层，焦点离开编辑器再回来，IME 状态不能乱。
- 500 命令 + 1 万文件时输入响应在一帧内。匹配放到后台时，要丢弃过期结果。
- Omnibox 改为打开面板（06 §2.3 的约定）。

### FE-2.3 侧栏面板（批次 8）

- 优先用 `ui.Outline` 做文件树 [源码]。1 万条目只构建可见行，先写计数断言。
- 三个面板共用 M1 的 `Segmented` 滑动药丸。
- 大纲的数据来自 AST，块 ID 稳定（BE-1.2），编辑时只更新变化的部分。

### FE-1.4 块视觉 v2（批次 9）

- 走 03 §6.5 的块注册表，不改引擎核心。
- 活动单元格、工具条不能改变行高，否则滚动锚点会跳。要有回归测试。
- 导轨只读 Fenwick 高度索引，1 万块时不能逐块排版，用 Stats 计数断言。

### FE-1.5 剪贴板与拖放（批次 10）

- 多格式写入用 `Clipboard.Write(transfer.Data)` [源码]，由 `adapters/clipboard` 包一层，测试用 `tt.Clipboard`。
- 粘贴图片时文档还未保存：先要求另存，或暂存到恢复目录，保存时再导入。负责人在这张卡开始时定，写入本文。
- 大段粘贴是一次撤销。

### FE-2.5 查找与横幅（批次 11）

- 横幅的 `Collapse` 不能让正文跳动（滚动锚点保持）。
- 冲突状态下的每个按钮都要有场景测试。“保留我的版本”走 `KeepMine`，“载入磁盘版本”走 `LoadTheirs` 且能撤销。
- 全部替换是一次撤销，大量命中时不能卡住界面。

### INT-2.1、QA-2.x（批次 12、13）

- 接线按 05。负责人亲自验证对话框。
- E2E 用 `plugins/automation`（`//go:build e2e`），覆盖 M2 全流程：打开文件夹 → 打开文件 → 编辑 → 自动保存 → 外部修改 → 解决冲突 → 重启恢复。能否进 CI [待验证]；进不了就在本机跑，并写明。
- 延续 Phase 1：`tests/qa` 零时间等待，M2 新风险各至少一个回归，语料保真和 1 万步属性测试继续跑。

## 7. 性能

| 项目 | 预算 | 证据 |
|---|---|---|
| ≤200 KB 击键 | 不比 M1 差：`BenchmarkTypeFrame` 约 1.1 ms；真窗口 p95 要有数据 | `tests/perf`、`tools/windowcheck` |
| 1 万块滚动 | 无整屏重排，导轨打开时也一样 | `TestScrollShapesNoWholeScreen` 加导轨 |
| 1 MB 文档查找 | < 5 ms | `BenchmarkFind` |
| 面板输入（500 命令 + 1 万文件） | 一帧内 | 计数或基准 |
| 文件树 1 万条目 | 只构建可见行 | 计数断言 |
| 空闲 | 面板和监听都打开时 0 帧 | `FramePending` |

M1 的真窗口数字包含等待屏幕刷新，不能直接和 8 ms 比。QA-2.x 在 `windowcheck` 里单独量一次帧工作时间（从构建开始到绘制结束），给 M1 这项差异一个能比较的数字。无窗口基准不算真窗口证据。

在 `tests/perf` 加一条分配次数或排版次数的断言，代替被放宽的墙钟上限，这样 CI 机器的抖动不影响它。
