# S4 外观与性能原型报告

结论标记：[实测] 本机运行得到；[待验证] 还没跑或要用户判断。

**当前结论：暂不下 Go/No-Go。** 性能、低功耗路径的令牌颜色和字体预算都通过；观感要用户在真机确认。

## 环境

- Windows 11，Ryzen 7 8845H，Radeon 780M + RTX 4060 Laptop，缩放 150%。窗口 1280×800 DIP。
- 没有确认 MyGo 实际用的是哪块 GPU，也没有在只有核显的机器上跑过。**弱 GPU 的帧率是 [待验证]。**

## 范围

`look.go` 按 `docs/design/baseline` 复现主界面外壳：窗口色调 + 纸张、三级玻璃（自写 `frost` Shader：背景模糊 + 饱和 + 填充 + 顶部高光）、ScrollEdge、滑动选中药丸（`Match`）、命令面板从 omnibox 长出（`Match`）、极光、主题径向溶解、低功耗路径。正文是静态文本，不含编辑器；图标用文字代替。

运行：

```bash
cd spikes/s4-look && go run .
```

默认注册 `fonts/`。可加 `-dark`、`-low`、`-welcome`、`-palette`、`-find`。标题栏的"查找 / 欢迎 / 低功耗 / 主题"可点。

## 帧耗时 [实测]

每项 300 步（约 4.9 s，每 16 ms 一步），`MYGO_FRAME_STATS=all`。"took" 是 CPU 侧耗时，不含 GPU 异步执行的时间；所以"60 fps"用每秒帧数和 took 一起判断。

| 场景 | 路径 | 绘制帧 | p50 ms | p95 ms | max ms（除首帧） | 每秒帧数 |
|---|---|---|---|---|---|---|
| 滚动（玻璃在上） | GPU | 276 | 1.1 | 1.7 | < 16.7 | 87–109 |
| 药丸滑动 | GPU | 371 | 0.7 | 1.4 | < 16.7 | 98–101 |
| 面板开合 | GPU | 383 | 1.1 | 1.9 | < 16.7 | 73–90 |
| 主题溶解 | GPU | 242 | 1.2 | 5.2 | < 16.7 | 56–71 |
| 极光 | GPU | 1225 | 0.0 | 0.6 | < 16.7 | 88–115 |
| 主题切换（交叉淡化） | `MYGO_GPU=0` | 196 | 2.5 | 35.0 | 36.0 | 37–47 |

- 每秒帧数包含内容未变化的帧，不等于每秒实际重绘次数。它说明帧循环没有掉队，不是 GPU 能力上限。
- 主题溶解最低 56 帧/秒，略低于 60。这是约 45 步一次、连续切换的压力场景，真实使用只有单次 400 ms。
- 首帧约 100–120 ms，其中 paint 约 80–98 ms，在 500 ms 冷启动预算内。
- `MYGO_GPU=0` 下动画到不了 60 fps，这个路径不要求 60 fps，但滚动和面板要降级：滚动 42 帧/秒、面板 p95 21 ms。

## 空闲与终止 [实测]

- 真实窗口静置 45 s：共 2 帧，都在启动的第 1 秒，之后 0 帧。
- 极光：约 13 s 后停止请求帧。Tester 断言 `FramePending()==false`。
- 药丸、面板、查找、主题、低功耗切换结束后都不再请求帧（`TestEffectsEnd`）。
- 低功耗路径的窗口和浮层颜色逐像素等于 02 §4.3 的令牌，浅深两种主题都一致（`TestLowPowerColors`）。

## 发现

1. **主题溶解要同时构建两份外壳。** 没有"截取上一帧"的接口，所以旧主题要再构建一遍。同一个 `ScrollState` 和 `Match` 不能绑两次（前者直接 panic），旧副本要用自己的滚动状态，且不带 `Match`。实现 FE-2 时要把外壳写成能重复构建的形式。
2. **Effect 首次使用可能卡一帧。** 第一次运行时主题切换有一帧 present 279 ms；之后的运行都没有再出现，推测是驱动缓存了编译结果，未证实。加预热的对比没有意义（缓存已热），预热代码已删。干净机器上的表现 [待验证]。
3. **模糊会读到元素外面。** `glass.Blur` 贴着纸张顶边时会读到窗口底色，纸张顶部发灰。解决：上面再盖一层 `glass.ScrollEdge{Background: sheet}`。
4. **绝对定位元素总画在普通元素之上。** 药丸和极光都盖住过文字，内容也要用 `Absolute`。
5. **系统窗口按钮不跟随应用主题。** 系统是浅色、应用用 `-dark` 时，右上角的按钮看不清。正式实现要同步窗口主题，或自绘按钮（`HideWindowButtons`）。接口没有验证。
6. **Tester 没有 GPU。** 它只能验证低功耗路径的外观；玻璃和极光的外观靠 `evidence/gpu-*.png` 和人眼。
7. **极光跟随屏幕刷新率**（本机约 115 帧/秒）。它变化很慢，正式实现用 `AnimationFrameRate(30)` 就够，能省电。
8. **MyGo 没有"减少透明度"的系统偏好**（`Preferences` 只有 `ReduceMotion`、`HighContrast` 等），这项要做成应用设置，走低功耗路径。
9. **`MYGO_GPU=0` 要自动走交叉淡化**：用上一帧的 `p.Accelerated()` 判断，已实现。

## 字体 [实测]

文件在 `fonts/`，均为 OFL，许可证里没有保留字体名，子集可以沿用原名。重新生成用 `fontsubset.py`。

| 文件 | 字节 | 说明 |
|---|---|---|
| `Noto_Serif_SC-gb2312-500-700.ttf` | 5,201,300 | GB2312 全部 6,763 字 + ASCII、Latin-1、CJK 标点，字重轴限制为 500–700 |
| `Newsreader-opsz-wght.ttf` | 451,664 | 未改动 |
| `Newsreader-Italic-opsz-wght.ttf` | 495,684 | 未改动 |
| `JetBrains_Mono-wght.ttf` | 187,208 | 未改动 |
| **合计** | **6,335,856** | 预算 15 MB |

Noto Serif SC 的其他子集方案：

| 字符集 | 500 单字重 | 700 单字重 | 500–700 可变 |
|---|---|---|---|
| 一级 3,755 字 | 1,689,484 | 1,689,428 | 2,830,908 |
| 一二级 6,763 字 | 3,100,116 | 3,100,068 | 5,201,300 |

**方案：一二级 + 500–700 可变字重**，预算足够，也用不着为常用字之外的字回退。

- 注册耗时：每个文件 1–4 ms，3 次运行合计约 6–8 ms，不会阻塞首帧。
- 首帧：2 次不注册 101–103 ms，3 次注册后 104–114 ms；layout 从 6–7 ms 变为 8–11 ms。
- 带字体滚动 300 步：p95 1.7 ms。
- `TestBundledFonts` 确认：各字体确实被找到（与不存在的字体绘制结果不同）、Noto 500 和 700 不同（可变字重生效）、Newsreader 斜体和正体不同、`Newsreader, Noto Serif SC` 混排用到了两种字体。
- 子集内部的家族名是 "Noto Serif SC ExtraLight"，**必须用 `RegisterFont(data, "Noto Serif SC")` 显式命名**，否则 `Font("Noto Serif SC")` 匹配不上。
- 中文斜体是合成的：Noto Serif SC 没有斜体字形。
- 未测：Newsreader 的光学尺寸轴（`opsz`）是否随字号自动变化；字体占用的内存；嵌入后的实际发布体积。
