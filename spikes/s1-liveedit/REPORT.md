# Spike S1 · 编辑引擎原型 报告

负责：FE-1 · 环境：Windows 11，Ryzen 7 8845H，Go 1.27.3，MyGo v0.7.3 · 标记：[实测] 本机运行 / [源码] 读源码 / [待验证] 未验证

## 1. 结论

**建议：Go。** 01 §6 的四项标准均已达到。Windows 微软拼音由用户真机检查通过，macOS、Linux 的 IME 不在本次范围内，仍未验证。进入 FE-1.1 时须覆盖 §6 第 1 项 `RevealInline` 这一最大遗留风险。

| Go 标准（01 §6） | 状态 | 依据 |
|---|---|---|
| 1 万块滚动无整屏重排 | **达标** [实测] | 每帧通常 1–3 块，最多一帧 6 块（预排版）；Tester 每屏可见 8 块 |
| 击键 p95 < 8 ms（≤ 200 KB） | **达标** [实测] | 真窗口引擎 1.81 ms + 帧呈现，合计不超过约 4.1 ms |
| 微软拼音组字、提交、候选框位置 | **达标**（用户真机检查） | §4 全部 10 项由用户答复通过；Tester 模拟也通过 |
| Tester 回归测试通过 | **达标** [实测] | 50 个测试全部通过（要求 ≥ 20），另有 1 个截图工具默认跳过 |

No-Go 后备（块级源码切换）不需要启用。

## 2. 测量数据

文档由 `liveedit.GenerateBlocks` / `GenerateBytes` 生成：标题、段落（1–3 句）、中英混排、内联语法。视口 1100×800（真窗口）或 1000×700（Tester）。

### 2.1 击键 [实测]

真窗口，`go run . -stress type`，400 次，每 60 键插入一次段落。计时从编辑开始到该帧绘制结束，包含字节替换、增量解析、重新分块、排版、绘制命令。200 KB 一轮有 8 次未计入（timed=392，两步并入同一帧，只记了后一步的起点）；1 MB 一轮 400 次全部计入。

| 文档 | 块数 | 引擎 p50 | 引擎 p95 | 引擎 max | 整帧 p50 / p95（`MYGO_FRAME_STATS`） |
|---|---|---|---|---|---|
| 200 KB | 961 | 1.09 ms | **1.81 ms** | 11.8 ms | 1.2 / 2.3 ms |
| 1 MB | 4783 | 1.69 ms | **2.85 ms** | 14.0 ms | 1.6 / 2.2 ms |

Tester（600 键，含无窗口绘制）：

| 文档 | p50 | p95 | 排版块数/键 | 单帧最多排版 |
|---|---|---|---|---|
| 200 块（42 KB） | 0.69 ms | 2.05 ms | 1.03 | 2 |
| 200 KB | 1.04 ms | 2.03 ms | 1.03 | 2 |
| 1 MB | 1.25 ms | 3.06 ms | 1.03 | 2 |
| 1 万块（2.1 MB） | 2.02 ms | 4.38 ms | 1.03 | 2 |

`BenchmarkTypeFrame200KB`：0.75 ms/op，576 KB/op，358 allocs/op。

**读数时的三个注意点：**

1. `MYGO_FRAME_STATS` 的整帧数字**不包含**编辑本身。编辑在帧之前的回调中完成，日志里 393/409 帧显示 0 次排版，只看它会低估。所以判定用的是引擎计时 + 帧呈现：两列 p95 直接相加约 4.1 ms，是偏保守的上界。
2. Tester 表的时间来自 `time.Now`，在本机呈约 0.5 ms 的台阶（p50 数字多为 0.5 ms 的倍数），只能看量级。
3. 最大值 11.8 / 14.0 ms 没有定位成因（开始前的光标跳转不在计时内），可能是 GC，[待验证]。这台机器性能较强，03 §10 写的「中端笔记本」目标机型没有测过。

### 2.2 滚动：每帧重新排版的块数 [实测]

| 场景 | 排版块数/次滚动 | 单帧最多 | 分布（块数→帧数） |
|---|---|---|---|
| 真窗口，1 万块，120 DIP × 300 | 约 1.5 | 6（不含下述跳转） | 0→12，1→152，2→143，3→5，6→1 |
| Tester，1 万块，120 DIP × 300 | 1.50 | 3 | 1→150，2→149，3→1 |
| Tester，200 块，120 DIP × 300 | 0.61 | 3 | 0→179，1→60，2→60，3→1 |

真窗口的 6 块出现在跳转之后，判断为预排版（每帧预算 6 块），未单独验证。

- 真窗口整帧 p50 1.6 ms、p95 2.5 ms；引擎 p50 1.03 ms、p95 1.76 ms。
- 回滚到已缓存区域：排版 0 块（`TestScrollBackReshapesNothing`，按计数断言）。
- 空闲：0 帧（`TestIdleIsZeroFrames`）。排版缓存有上限（`TestLayoutsAreBounded`）。
- **跳转不在此列**：光标或滚动一次跳到未排版的远处时，会有一帧排版整屏（真窗口日志中 18–22 块）。这是无法避免的，但不属于滚动重排。

### 2.3 启动 [实测]

首帧 112–120 ms，其中呈现 92–96 ms。本次第一次运行时首帧为 1915 ms（呈现 1848 ms），推测是 GPU 管线的冷启动，[待验证]。这与 03 §10 的「冷启动 < 500 ms」预算有关，建议 INT/QA 在 FE-1.1 后单独测量。

## 3. 实现摘要

```
spikes/s1-liveedit/
  main.go                 go run . 演示窗口；-stress type|scroll 自驱压测
  liveedit/document.go    源码 + parser.Document 增量解析 + 无缝分块 + BlockID 映射
  liveedit/project.go     投影（contract.Segment）与 toDisplay/toSource/snap
  liveedit/heights.go     Fenwick 高度树
  liveedit/editor.go      双形态块缓存、虚拟滚动、滚动锚定
  liveedit/input.go       键盘、指针、历史
  liveedit/ime.go         ui.TextInputClient
  liveedit/paint.go       样式、绘制、页边标签、结构导轨
```

- **源码是唯一真相** [实测]：光标、选区、历史都是字节偏移；所有写入都经过 `applyEdit`。`TestRandomEditsMatchStringModel` 用 3 个种子各跑 400 步随机操作，每步与字符串模型对比，全部撤销后逐字节回到原文。
- **双形态缓存**：每块缓存「隐藏」和「显示标记」两份排版，光标路过已缓存块时不排版。键入只作废被触及的块。
- **自滚动（解决 03 §6.1 的待定项）**：采用自滚动，不用 `ui.Scroll`。滚动由「锚定块 + 块内偏移」决定，块高变化要在测量它的同一帧修正偏移；`ui/richtext` 也是这样做的 [源码]。
- **预编辑** [实测，Tester]：只是排版时多一个带下划线的 span。组字不产生编辑，取消不留历史，提交是一次编辑、一步撤销；组字覆盖选区时，删除选区和提交合为一步。
- **已截图检查** [实测]：标记显隐、衬线混排、预编辑下划线、跨块选区的渲染结果都正确。

### 视觉基线的支撑能力（不要求 S1 达到）

| 基线要素 | 结构上如何支撑 | 状态 |
|---|---|---|
| 衬线混排 | 块字体和 span 字体互相独立，可按块、按片段指定字体族列表；字体变化只影响 `blockFont`/`styled` | [实测] H1/H2 用衬线回退栈，中西混排正确。Newsreader 与 Noto Serif SC 未打包，回退到系统字体，真实字体由 S4 决定 |
| 页边标签 | 与块排版分开缓存，切换活动块不重排正文 | [实测] 已绘制 `¶`、`H2` |
| 结构导轨 | 只读 Fenwick 树，不排版任何块 | [实测] 已绘制标题刻度和视口滑块；未做拖动和查找命中 |
| 块间距 | `blockSpace` 计入高度树 | [实测] 按 02 §4.2 |

**尚未覆盖**：H1 字距、导语、悬挂引号、列表符号、代码块组件、块组件注册表、深色主题。

## 5. 对契约的修改建议

| CR | 内容 | 依据 |
|---|---|---|
| [CR-001](../../docs/cr/CR-001-blank-lines.md) | 块间空行没有归属，光标无处可放：增加空行叶子和块尾区间 | [实测] `TestEnterOnEmptyBlockAndAtEnd` 等 |
| [CR-002](../../docs/cr/CR-002-projection-offsets.md) | 投影的 `Sig` 不受绝对偏移影响；`Display` 不得零拷贝引用源码；明确 `Affinity` 在隐藏边界的语义 | [实测] 缓存需要 `rebase`；[源码] 子串会钉住整个字符串 |

**不需要改的：**

- `Reveal`、`SegKind`、`PosMapper` 的语义足以支撑 S1。预编辑留在视图层即可，不需要进契约。
- `editorapi.Controller` 没有发现需要改的地方。注意 `Focus()` 没有 `*ui.Context` 参数，而 `Handle.Focus` 需要它，实现时要记下请求，到下次构建再执行（[源码]，S1 未实现 Controller）。

S1 未实现 `contract.Projector` 接口的 `Project`，因为它需要完整的 `contract.AST`；但用的是 `contract.Segment`、`BlockProjection` 类型，映射函数签名也一一对应。

## 6. 已知限制与风险

1. **`RevealInline` 没有验证，这是最大的遗留风险。** 任务卡要求按块显隐，基线 `Main.png` 和契约默认值却是内联显隐。按块显隐时活动块的标记全部可见，光标不会遇到隐藏片段；内联显隐下，光标要在同一块内跨过隐藏标记，每移一步都可能改变显示文本。映射函数已在隐藏形态上通过属性测试，但这种移动没测。BE-1.3 与 FE-1.1 需要专门覆盖。
2. **真实 IME 的调用顺序只读了源码。** Windows 走 IMM32（`internal/windows/surface.go`）[源码]。Tester 不经过它，提交前后 `UnmarkText`、`SetMarkedText("")` 的实际次序没有记录，§4 只验证了用户可见的行为。macOS、Linux 的 IME 未验证，微软拼音以外的输入法也未验证。
3. **`BlockID` 是简化实现**：按「未触及或起点不变」继承，未经语料验证，由 S3 负责。未被触及的块若因引用式链接定义改变而内联变化，缓存不会失效；FE-1.1 应改用 `Block.Revision()`。
4. **语法范围**：只投影标题和段落的粗体、斜体、行内代码。其他块和内联按源码原样显示，保持无损。转义、实体、容器前缀没有投影。
5. **历史是原型**：相邻键入合并，没有 1 秒时间窗；正式实现归 `core/document`。
6. **未实现**：词级移动、双击/三击、拖选时自动滚动、导轨拖动。
7. **每次键入 O(块数)**：重新分块和 ID 映射都遍历全部块。1 万块下仍在预算内，但 1 万块时 p95 从 2 ms 升到约 4 ms，大文档需留意。
